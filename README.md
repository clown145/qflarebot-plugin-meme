# 表情包插件（qflarebot-plugin-meme）

适用于 [QFlareBot](https://github.com/QFlareBot/QFlareBot) 的表情包制作与图片工具插件，后端对接 [meme-generator-rs](https://github.com/MemeCrafters/meme-generator-rs)。

移植自 [astrbot_plugin_mememaker_api](https://github.com/jmt059/astrbot_plugin_mememaker_api)，按 Cloudflare Workers 免费版的额度重写，并修了原版的几个 bug（见文末）。

## 部署前提

先自己部署一个 meme-generator-rs（[Docker 部署](https://github.com/MemeCrafters/meme-generator-rs/wiki/Docker-%E9%83%A8%E7%BD%B2)），并让它**有公网域名、走 443 端口**：

- Worker 要调它生成表情。Workers 不能直接请求 IP 地址，非标准端口（默认的 2233）也不通；
- 生成好的图不经过 Worker，插件把 `https://<meme 服务>/image/<id>` 直接交给 QQ 去拉，所以 QQ 也要能访问到。

用 Cloudflare Tunnel 或任意反向代理把服务挂到一个域名上即可。插件用 D1 存目录和等待会话，机器人需要绑定 D1。

### 部署在 ModelScope 创空间这类要鉴权、又访问不了外网的平台

- 把访问令牌（`ms-…`）填进 `token`，插件请求 meme 服务时会带上 `Authorization: Bearer`；
- QQ 拉图带不了令牌，图片改由本插件的公开路由 `/p/meme/image/<id>` 带着令牌取回、流式转给 QQ，不把图片读进内存。拼这个地址要知道机器人自己的公开地址：QFlareBot 0.4 起插件自己就拿得到，`public_base_url` 不用填；更老的机器人要填上；
- 这类平台的容器通常访问不了外网，meme 服务没法自己下载头像。`upload_mode` 默认的 `auto` 会在第一次下载失败后改由 Worker 下载、用 multipart 上传（不转 base64），也可以直接设成 `worker`。

## 用法

`关键词 [文字…] [@人 / 图片] [--选项]`

- 群里 @ 机器人或单聊时直接发关键词：`摸 @张三`、`举牌 你是谁来着`
- 没 @ 机器人时加前缀（默认 `/`）：`/摸 @张三`、`/摸 -圆`
- 快捷指令整句匹配：`/满脑子都是张三`、`/低情商 xxx 高情商 yyy`
- 图片来源：@ 的人的头像（名字用对方昵称）、消息里的图片；图不够时自动补上发送者头像
- 参数不够时插件会等你接着发（默认 60 秒），直接发图片、@ 人或文字即可，发送「取消」终止

## 配置

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `base_url` | — | meme 服务地址（必填） |
| `token` | 空 | 访问令牌（可选），填了就带 `Authorization: Bearer`。QFlareBot 0.4 起面板不回显，只显示「已设置」 |
| `public_base_url` | 空 | 机器人公开地址，只接受 https。只在配了令牌时用，图片经本插件路由转给 QQ。不填时用机器人设置里的公开地址（QFlareBot 0.4 起）；更老的机器人必须填 |
| `upload_mode` | `auto` | `url`：meme 服务自己下载图片；`worker`：Worker 下载后上传；`auto`：先试 `url`，失败一次后改用 `worker` |
| `timeout` | 15 | 单次请求超时（秒）。整次处理最多 30 秒，别设太长 |
| `prefixes` | `["/"]` | 没 @ 机器人时关键词要带的前缀，建议与面板的命令前缀一致 |
| `bare_keywords` | 关 | 不 @ 也不带前缀，以关键词开头就触发 |
| `fuzzy_match` | 开 | 带前缀时关键词后可以不加空格（`/摸摸头张三`） |
| `use_sender_when_no_image` | 开 | 图不够时用发送者头像 |
| `interactive` | 开 | 参数不够时等待补充 |
| `interactive_timeout` | 60 | 等待补充的秒数 |
| `label_new_days` | 7 | 表情列表里几天内的算「新」 |

## 资源占用

- **图片尽量不过 Worker**：上传时让 meme 服务自己按 URL 下载，生成结果直接把地址给 QQ，Worker 不下载、不编码。做一个表情的子请求是：每张不同的图上传 1 次、生成 1 次，再加 QQ 发图。
  - meme 服务下载不了时（`worker` 上传），每张图多 1 次下载，只是内存拷贝，不转 base64；
  - 配了令牌时，QQ 拉图会走一次本插件的转发路由（多 1 次 Worker 请求、1 次子请求，流式转发不占 CPU）。
- **目录**：`/meme/infos` 压成精简索引存进 D1 的一行，每个 isolate 缓存在内存里、每小时确认一次有没有更新。每天定时比对一次 meme 服务版本，变了才重建。不用 KV。
- **每条消息**：开着交互式时，没被其他命令接走的消息会多一次 D1 主键读（不写入）；关掉交互式就没有这次读。没 @、没前缀的群消息不加载目录、不请求 meme 服务。
- **写入**：只有交互时才写。开会话 1 行，每补一次 1 行，结束 1 行。

D1 表都不会越存越多：

| 表 | 内容 | 为什么不会膨胀 |
| --- | --- | --- |
| `catalog` | 表情目录 | 只有一行，刷新是覆盖 |
| `sessions` | 等待补参数 / 搜索翻页 | 每个人在每个群最多一行，做完、取消即删；超时没人理的每天凌晨一条 DELETE 清掉 |

两张表都是 `WITHOUT ROWID` 且只有主键，没有额外的索引行。

兜底规则是一条最低优先级的正则，所以面板「最近事件」里每条没被别的插件接走的消息都会显示命中了本插件，这是正常的。

## 与 AstrBot 版的不同

修掉的 bug：

- **会画进图里的名字全是 `img0`**：原版上传图片时把 `name` 写死成 `img0`、`img1`，问问、我朋友说、小天使、请假条、复读、满脑子、关注、一起、炖、兑换券等 20 个表情都画成了 img0，表情自己「没名字就写他/她」的兜底也因此失效。现在 @ 的人用对方昵称，发送者头像用发送者昵称，直接发的图片留空。
- **快捷指令捕获的名字被丢掉**：「满脑子都是张三」原来画的还是 img0，现在是张三。
- **选项串到后面的请求**：原版用了可变默认参数，用过一次 `--number 3` 之后，没写编号的请求也一直带着 3。
- **表情详情不显示可选值和范围**：原版的数据模型没声明 `choices` / `minimum` / `maximum`，解析时被丢掉了。
- **关键词区分大小写**：「哆啦a梦说」「Steam消息」原来触发不了。
- **`/gif合成` 只用前两张图**：现在用上消息里所有的图。

按平台去掉的功能：合并转发与 zip 打包（QQ 官方机器人不支持）、表情禁用与插件管理员（分群开关用面板的「生效的群」）、使用统计、提示消息撤回、超时提醒（Worker 里没有常驻计时器，超时的会话静默作废）。

文案沿用上游原句；meme 服务报了具体原因时补在原句后的括号里。「正在搜索…」「正在生成动态列表…」「参数已集齐，开始制作...」这类纯进度提示不发，每条都要多一次 QQ 调用。

## 构建与测试

SDK 与 `qqbot-plugin` 不发 npm，要把 [QFlareBot](https://github.com/QFlareBot/QFlareBot) 克隆到本仓库旁边并先构建（见 QFlareBot 的插件开发指南）。

```bash
npm install
npm test          # 测试用 Node 自带的 SQLite（Node 22.5+）跑真 SQL，并过框架同一份表名检查
npm run build     # 生成 dist/plugin.js 与 dist/manifest.json
npm run sync      # 把清单同步到根目录，随代码提交
```
